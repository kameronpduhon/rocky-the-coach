# P4f: SPA Mode Implementation Plan

> **For agentic workers:** implement this plan task-by-task with the `executing-plans` skill. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** React Router switches to SPA mode (`ssr: false`). The build writes one `index.html` that opens any path, Cloudflare serves it from static assets with the single-page fallback, the Worker still answers `/api/*` and `/media/*` first, and the service worker precaches the shell so a cold open with no signal still paints from IndexedDB.

**Architecture:**
- **Config:** `react-router.config.ts` sets `ssr: false`. `wrangler.jsonc` gains `assets` with `binding: "ASSETS"`, `not_found_handling: "single-page-application"` and `run_worker_first: true`. The Cloudflare Vite plugin fills in the directory (`build/client`) at build.
- **The Worker's fetch, in order:** the https redirect, then `routeApi` (`/api/*`, `/media/*`, from P4e), then a 404 for any `*.data` request, then `env.ASSETS.fetch(request)`.
- **React Router's handler stays in the Worker, as a shell renderer only.** See "Calls made". It renders when the assets have no file for a navigation, which happens only at build time (the prerender of `index.html` runs through this Worker in `vite preview`) and under `npm run dev`.
- **Service worker:** precaches `/` (the shell) with the build's assets. A navigation is network-first; offline it gets the precached shell. The v1 page cache, which holds server-rendered pages whose scripts are gone, is deleted.

**Tech Stack:** React Router 8.4 framework mode, `@cloudflare/vite-plugin` 1.62, Workers static assets, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-10-28-checkin-plan-progress-library-design.md`, section 4 "The flip (P4f)", call 21 ("SPA serving"), section 5 (the "phone on the SSR build after P4f" row), section 6 rollout step 6, Testing ("P4f" and "On the wire"). **Previous step:** `docs/superpowers/plans/2026-10-28-p4e-worker-endpoints.md`, which must be live. **Branch:** `v2/p4-checkin-plan-progress-library`, worktree `/Users/kameron/Code/rocky-wt/p4`.

**There are no migrations in P4f.**

## What was confirmed, and how

| Question | Answer | Source |
|---|---|---|
| What `ssr: false` builds | One `build/client/index.html` that renders only the root route and hydrates any path. Only the root may have a `loader`; no route may export `action`, `headers` or (in 8.x) `middleware`. A route with only a `clientLoader` gets `hydrate = true` implied, and its `HydrateFallback` shows until it resolves. The root's `HydrateFallback` goes into `index.html` | React Router docs, "Single Page App (SPA)" and "Pre-rendering with ssr:false" (reactrouter.com/how-to/spa, /how-to/pre-rendering), "Client data" (/how-to/client-data); `@react-router/dev` 8.4 `SERVER_ONLY_ROUTE_EXPORTS = ["loader", "action", "middleware", "headers"]`, refused in SPA builds |
| Serving it from a Worker | `assets.not_found_handling: "single-page-application"` serves `index.html` for paths with no file; `run_worker_first: true` runs the Worker for every request; `env.ASSETS.fetch(request)` applies the same handling from the Worker. With the Vite plugin the `directory` is filled in at build | Cloudflare docs, "Static assets: binding", "run_worker_first", "SPA shell" example, "Tutorial: React SPA with an API" (developers.cloudflare.com/workers) |
| SPA mode with the Cloudflare Vite plugin | Cloudflare's React Router guide says "SPA mode and prerendering are not currently supported when using the Cloudflare Vite plugin". The reason: React Router renders `index.html` by sending `GET /` with `X-React-Router-SPA-Mode: yes` to a `vite preview` server, and the plugin's preview middleware sends every request to the built Worker. So the Worker must still be able to render the shell | Cloudflare docs, "React Router (formerly Remix)"; `@react-router/dev` 8.4 `prerender()` and `createSpaModeRequest`; `@cloudflare/vite-plugin` 1.62 `previewPlugin` |
| That this plan's shape works | A throwaway project with the installed versions, `ssr: false`, these assets settings and this fetch order: `react-router build` prints "SPA Mode: Generated build/client/index.html" and the file has `"isSpaMode":true` and the root's `HydrateFallback`. `vite preview`: `/` and `/plan` give the shell (200), `/plan.data` 404, `/api/me` reaches the Worker, `/index.html` is a 307 to `/`. `react-router dev`: `/` and `/plan` give the shell. The workers test pool loads a `wrangler.jsonc` whose `assets` has no `directory`, with no `ASSETS` binding | Spike run on 2026-10-28 in the session scratchpad |
| The experimental alternative | `@cloudflare/vite-plugin` 1.62 has `experimental.prerenderWorker` (a separate Worker only for the prerender). In the spike, `react-router build` failed with it: the preview server started before `.wrangler/deploy/config.json` was written | Same spike |

## Calls made in this plan (flag them when shipping)

- **The React Router server build stays in the deployed Worker.** The spec says it leaves `workers/app.ts` and the plugin stops building an SSR environment. With the Cloudflare Vite plugin that breaks the build (above), and the plugin's experimental prerender Worker failed in the spike. The Worker keeps `createRequestHandler`, but calls it only when the assets have no file for a navigation (`Sec-Fetch-Mode: navigate` or the build's `X-React-Router-SPA-Mode`). In production every navigation finds `index.html`, so it never runs. The Worker bundle stays the size it is today.
- **`/` is precached, not `/index.html`.** The assets layer answers `/index.html` with a 307 to `/`, and a redirected response can't answer a navigation.
- **The shell is not re-cached on every online navigation.** Every path is the same file, versioned by the build's precache, so the v1 per-URL page cache goes.
- **`run_worker_first: true`,** as the spec says, so every request (assets too) goes through the Worker and the https redirect. A Worker request per asset load is negligible for two people. `["/*", "!/assets/*"]` would skip the Worker for hashed assets if it ever matters.
- **The wire check for "no loader data" looks for `"isSpaMode":true`.** The spec says `loaderData` must not appear, but the SPA shell's hydration script names a `loaderData` key even with nothing in it (seen in the spike).

```ts
import { readFileSync } from "node:fs";
import { join } from "node:path";
import { describe, expect, it } from "vitest";
import { stampServiceWorker } from "../../scripts/precache-sw";

const ORIGIN = "https://kampduh.com";
// sw.js as a build stamps it, for a build with one script.
const BUILT = stampServiceWorker(readFileSync(join(import.meta.dirname, "../../public/sw.js"), "utf8"), ["/assets/root-abc.js"]);
const ASSETS = `rocky-assets-${BUILT.match(/VERSION = "(\w+)"/)![1]}`;

type Req = string | { url: string };
type Handler = (event: Record<string, unknown>) => void;
const href = (r: Req) => new URL(typeof r === "string" ? r : r.url, ORIGIN).href;

const online = async (url: string) => new Response(url === `${ORIGIN}/` ? "shell" : `file ${url}`);
const offline = async (): Promise<Response> => {
  throw new TypeError("Load failed");
};

/** Runs sw.js against in-memory caches and a network the test can switch off. */
function boot(seed: Record<string, Record<string, string>> = {}) {
  const net = { fetch: online };
  const stores = new Map<string, Map<string, Response>>(
    Object.entries(seed).map(([name, files]) => [name, new Map(Object.entries(files).map(([path, body]) => [href(path), new Response(body)]))]),
  );
  const store = (name: string) => stores.get(name) ?? stores.set(name, new Map()).get(name)!;
  const caches = {
    open: async (name: string) => {
      const s = store(name);
      return {
        match: async (r: Req) => s.get(href(r))?.clone(),
        put: async (r: Req, res: Response) => void s.set(href(r), res),
        addAll: async (paths: string[]) => {
          for (const p of paths) s.set(href(p), await net.fetch(href(p)));
        },
      };
    },
    keys: async () => [...stores.keys()],
    delete: async (name: string) => stores.delete(name),
    match: async (r: Req) => {
      for (const s of stores.values()) {
        const hit = s.get(href(r));
        if (hit) return hit.clone();
      }
      return undefined;
    },
  };
  const handlers: Record<string, Handler> = {};
  const self = {
    location: { origin: ORIGIN },
    addEventListener: (type: string, fn: Handler) => (handlers[type] = fn),
    skipWaiting: async () => {},
    clients: { claim: async () => {} },
    registration: {},
  };
  new Function("self", "caches", "fetch", BUILT)(self, caches, (r: Req) => net.fetch(href(r)));

  async function dispatch(type: string, extra: Record<string, unknown> = {}) {
    let response: Promise<Response> | undefined;
    const waits: Promise<unknown>[] = [];
    handlers[type]({ ...extra, respondWith: (p: Promise<Response>) => (response = p), waitUntil: (p: Promise<unknown>) => waits.push(p) });
    await Promise.all(waits);
    return response;
  }
  return { net, stores, dispatch };
}

const navigate = (path: string) => ({ request: { method: "GET", url: `${ORIGIN}${path}`, mode: "navigate" } });

describe("the service worker", () => {
  it("precaches the shell with the build's assets", async () => {
    const sw = boot();
    await sw.dispatch("install");
    expect([...sw.stores.get(ASSETS)!.keys()]).toEqual([`${ORIGIN}/`, `${ORIGIN}/assets/root-abc.js`]);
  });

  it("opens any path with no signal, from the precached shell", async () => {
    const sw = boot();
    await sw.dispatch("install");
    sw.net.fetch = offline;
    for (const path of ["/", "/plan", "/meal/steak-and-eggs?slot=dinner"]) {
      expect(await (await sw.dispatch("fetch", navigate(path)))!.text(), path).toBe("shell");
    }
  });

  it("takes the network's page when there is a signal, so a new deploy shows on the next open", async () => {
    const sw = boot();
    await sw.dispatch("install");
    sw.net.fetch = async () => new Response("new shell");
    expect(await (await sw.dispatch("fetch", navigate("/plan")))!.text()).toBe("new shell");
  });

  it("drops the server-rendered pages and older builds, and keeps exercise photos", async () => {
    const sw = boot({
      "rocky-pages-v1": { "/plan": "an SSR page whose scripts are gone" },
      "rocky-assets-0123456789ab": { "/assets/old.js": "old" },
      "rocky-media-v1": { "/media/exercises/Butterfly/0.jpg": "img" },
    });
    await sw.dispatch("install");
    await sw.dispatch("activate");
    expect([...sw.stores.keys()].sort()).toEqual([ASSETS, "rocky-media-v1"].sort());
  });
});
```

- [ ] **Step 3: The Worker's fetch order.** Replace `workers/app.ts` with:

```ts
import { createRequestHandler } from "react-router";
import { runScheduled } from "../app/jobs/scheduled";
import { routeApi } from "./api/router";
import { httpsRedirect } from "./https";

export { RestTimer } from "../app/server/rest-timer.server";

// SPA mode serves the built index.html for every app path. React Router's handler only renders that shell when the
// assets have no file for a navigation: at build time (the prerender of index.html runs through this Worker in
// `vite preview`) and under `npm run dev`. In production every navigation finds index.html.
const renderShell = createRequestHandler(() => import("virtual:react-router/server-build"), import.meta.env.MODE);

const navigating = (request: Request) => request.headers.get("Sec-Fetch-Mode") === "navigate" || request.headers.has("X-React-Router-SPA-Mode");

export default {
  async fetch(request, env) {
    const toHttps = httpsRedirect(request);
    if (toHttps) return toHttps;
    const api = await routeApi(request);
    if (api) return api;
    // Only a phone still running the SSR build asks for loader data. There is none now; its error page offers Reload.
    if (new URL(request.url).pathname.endsWith(".data")) return new Response("Not found", { status: 404 });
    const asset = await env.ASSETS.fetch(request);
    if (asset.status === 404 && navigating(request)) return renderShell(request);
    return asset;
  },
  async scheduled(controller, env, ctx) {
    ctx.waitUntil(runScheduled(env, controller.cron, new Date(controller.scheduledTime)));
  },
} satisfies ExportedHandler<Env>;
```

## Deploy safety: phones on an older build

- **A phone on the P4e build** never asks for `*.data`: P4e left no server loaders. On its next open, the network-first navigation loads the new shell; the browser fetches `/sw.js`, sees new bytes, installs the new worker (precaching `/`), and it takes over with `skipWaiting` and `clients.claim`. Its activate deletes `rocky-pages-v1`.
- **A phone opened offline before it updates** runs its old worker, which serves its cached P4e page and its precached P4e scripts: the app works offline as before. Back online, the next open updates it as above.
- **A tab left open across the deploy** keeps running its P4e scripts. Its route chunks are precached by its old worker, so screens keep opening. If anything fails to load, P4e's error page has Reload.
- **A phone still on a pre-P4e build** (not opened since before P4e shipped) asks for `*.data` on its first in-app navigation, gets the 404, and shows its old error page without Reload. Closing and reopening the app loads the new shell. Two people use the app daily, so this window is effectively closed.
