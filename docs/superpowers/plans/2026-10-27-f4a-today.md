# F4a: Today on the Store Implementation Plan

> **For agentic workers:** implement this plan task-by-task with the `executing-plans` skill. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Today is rebuilt from the approved Corner mocks, and it reads and writes the phone's copy of the data. "Ate it", a weigh-in or an off-plan item paints in the same frame and saves offline. The new habit rules apply: counted days, a forgiving streak, and two off-plan desserts a week.

**Architecture:**
- **Pure model.** `buildToday(rows, now, hasPlan)` in `app/today/model.ts` turns the store's raw rows into everything Today shows. It is pure, so it runs in the browser and in Node unit tests.
- **Domain rules.** It leans on two new domain modules: `app/domain/habits.ts` (counted day, streak, dessert allowance, full day) and `app/domain/next-up.ts` (which poster shows).
- **Screen.** Today's route has no loader or action any more. The component reads the store through hooks and writes through the F2 mutators.
- **App layout.** The layout's loader tells Today who is signed in and whether they have a plan. It also makes sure this week's meals are planned, so they exist to sync down.
- **Components.** The first pieces of the `app/ui/` kit are built here, each sized from the mocks: `Poster`, `btn`, `SectionHead`, `RockyCard`, `ProgressionCallout`, `ProteinBar`, `WeekStrip`.

**Tech Stack:** React Router 8.4 (framework mode, SSR stays on), the F2 sync layer, Tailwind 4 with the F3 tokens, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-10-27-foundation-design.md`, section 4 ("Today" and "Habit rules"), the error table, and rollout step 4. **Branch:** `v2/f4-today` (already created from `main` after F3 merged). **Mocks:** artboards `Corner2` (before the lift) and `Corner2Lunch` (after it) on https://claude.ai/artifact/65WeReuGH5ZageJng9K6nq. **Design system:** `docs/design/system.md`.

**F4 is split in two.** This plan (F4a) covers Today and the habit rules. F4b, written after this merges, covers Settings, Login and the service worker's offline shell.

**Calls made in this plan (flag them in the PR):**
- **No `clientLoader` for Today.** Today reads the store with hooks instead. The sync client lives in a React provider that a `clientLoader` cannot reach. Hooks also repaint on every store change, which a loader would only do after a revalidation. The server render shows an empty, `aria-busy` page until the store is ready.
- **The layout loader plans the week.** It calls `ensureWeekPlan` on every navigation for people with a plan. That costs one cheap read when the week already exists. Offline on a Monday morning before the week has synced, Today falls back to the first fitting meal for each slot, the same rule `plannedForDate` uses.
- **Store freshness.** The store pulls on every navigation, as well as on open and every 60 s. A workout logged on the v1 workout screen therefore shows on Today right after you go back.
- **Undoing a meal.** The "Eaten" mark on a meal row is a button that undoes the meal (`unlogMeal`). Editing a weigh-in stays on Progress (the v1 sheet) until project 4.
- **"Swap" on the meal poster** opens the v1 meal screen, where the swap sheet already lives.
- **Long meal names.** The poster drops from 68 px to 64 px when any line runs past 12 characters, so long meal names wrap instead of overflowing.
- **v1 meal screen.** `day.server.ts` (only the v1 meal screen uses it now) keeps its old "any dessert breaks the day" test. `dayResults`, which feeds the check-in and Progress counts, switches to the allowance rule as the spec says.
- **Two F2 review follow-ups land here, now that screens send changes:**
    - The client sends at most 500 changes per push.
    - A change that crashes the server, rather than being turned down, is rejected and reported instead of retried forever.
    - A database outage during a change is still retried, never dropped.
- **Rejected changes are named.** The one-line notice names what did not save, for example "Weigh-in didn't save. That date is in the future."

```ts
import { addDays, weekStart } from "./dates";
import type { ISODate } from "./types";

export const DESSERT_ALLOWANCE = 2;
export const COUNTING_STEPS = 3000;

/** What happened on one day, for the habit rules. */
export interface DayActivity {
  weighIn: boolean;
  mealLogged: boolean;
  /** A set logged or an exercise checked off. */
  workout: boolean;
  steps: number;
  relaxed: boolean;
}

/** A day counts if any one thing happened. Relaxed days in the plan always count. */
export function countedDay(a: DayActivity): boolean {
  return a.relaxed || a.weighIn || a.mealLogged || a.workout || a.steps >= COUNTING_STEPS;
}

/**
 * Counted days walking back from today. A single uncounted day is stepped over, not broken; two in a row end it.
 * Today only ever adds: until it is over it cannot break anything.
 */
export function habitStreak(counted: (d: ISODate) => boolean, today: ISODate, firstDay: ISODate): number {
  let count = counted(today) ? 1 : 0;
  let gap = 0;
  for (let d = addDays(today, -1); d >= firstDay; d = addDays(d, -1)) {
    if (counted(d)) {
      count++;
      gap = 0;
    } else if (++gap === 2) {
      break;
    }
  }
  return count;
}

/** The dessert row's words. Over the allowance it is just the count, in the same ink: no warning. */
export function dessertAllowance(usedThisWeek: number): string {
  return usedThisWeek <= DESSERT_ALLOWANCE ? `${DESSERT_ALLOWANCE - usedThisWeek} of ${DESSERT_ALLOWANCE} left this week` : `${usedThisWeek} this week`;
}

/** Days with an off-plan dessert past the second of its Monday-to-Sunday week. */
export function overAllowanceDates(desserts: { date: ISODate; at: string }[]): Set<ISODate> {
  const perWeek = new Map<ISODate, number>();
  const over = new Set<ISODate>();
  for (const d of [...desserts].sort((a, b) => a.date.localeCompare(b.date) || a.at.localeCompare(b.at))) {
    const week = weekStart(d.date);
    const n = (perWeek.get(week) ?? 0) + 1;
    perWeek.set(week, n);
    if (n > DESSERT_ALLOWANCE) over.add(d.date);
  }
  return over;
}

export interface FullDayFacts {
  proteinG: number;
  proteinTarget: number;
  steps: number;
  stepGoal: number;
  relaxedDay: boolean;
  overAllowance: boolean;
}

/** The check-in's "full day": protein and steps met, and no dessert past the week's allowance. */
export function fullDay(f: FullDayFacts): boolean {
  if (f.relaxedDay) return true;
  return f.proteinG >= f.proteinTarget && f.steps >= f.stepGoal && !f.overAllowance;
}
```

```ts
import type { ISODate } from "./types";

/** The Monday of the week whose check-in is open now: Sunday 5pm until Monday noon. Otherwise null. */
export function checkInWindow(now: Date): ISODate | null {
  const today = localDate(now);
  const minutes = localMinutes(now);
  const wd = weekday(today);
  if (wd === 0 && minutes >= 17 * 60) return weekStart(today);
  if (wd === 1 && minutes < 12 * 60) return addDays(weekStart(today), -7);
  return null;
}
```

```ts
import type { Slot } from "./types";

export type NextUp =
  | { kind: "check-in" }
  | { kind: "workout"; templateId: string; started: boolean }
  | { kind: "meal"; slot: Slot }
  | { kind: "steps"; left: number }
  | { kind: "done" }
  | { kind: "no-plan" };

export interface NextUpDay {
  hasPlan: boolean;
  /** Minutes since midnight of the meal day. Late night (before 3am) runs past 24:00. */
  minutes: number;
  checkInOpen: boolean;
  /** In time order. */
  slots: { slot: Slot; minutes: number; eaten: boolean }[];
  workout: { templateId: string; started: boolean; finished: boolean } | null;
  steps: number;
  stepGoal: number;
}

export const WORKOUT_START = 12 * 60;
/** A workout never started stops being "next" when its plan window closes. */
export const WORKOUT_CLOSE = 14 * 60;
const DAY_END = 27 * 60;

/** The one thing Today's poster is about. */
export function nextUp(day: NextUpDay): NextUp {
  if (!day.hasPlan) return { kind: "no-plan" };
  if (day.checkInOpen) return { kind: "check-in" };
  const items: { at: number; ends: number; done: boolean; up: NextUp }[] = day.slots.map((s, i) => ({
    at: s.minutes,
    ends: day.slots[i + 1]?.minutes ?? DAY_END,
    done: s.eaten,
    up: { kind: "meal", slot: s.slot },
  }));
  if (day.workout) {
    const w = day.workout;
    items.push({ at: WORKOUT_START, ends: w.started ? Infinity : WORKOUT_CLOSE, done: w.finished, up: { kind: "workout", templateId: w.templateId, started: w.started } });
  }
  items.sort((a, b) => a.at - b.at);
  const current = items.find((i) => !i.done && day.minutes < i.ends);
  if (current) return current.up;
  if (day.steps < day.stepGoal) return { kind: "steps", left: day.stepGoal - day.steps };
  return { kind: "done" };
}
```

```ts
function lastSets(rows: Rows, exerciseId: string, before: ISODate): LoggedSet[] | null {
  const dateOf = new Map(rows("workout_sessions").map((r) => [n(r, "id"), s(r, "date")]));

/** The last two training days before today both had no workout, and nothing was logged since the first of them. */
function missedTwoInARow(today: ISODate, setDates: Set<ISODate>, moves: Moves): boolean {
  const missed: ISODate[] = [];
  for (let d = addDays(today, -1); missed.length < 2 && d >= addDays(today, -14) && d >= plan.phaseStart; d = addDays(d, -1)) {
    if (!isTrainingDay(plan, d, moves)) continue;
    if (setDates.has(d)) return false;
    missed.push(d);
  }
  if (missed.length < 2) return false;
  for (const d of setDates) if (d > missed[1]) return false;
  return true;
}

function countedLine(a: DayActivity, weighInTime: string | null, firstMeal: string | null, relaxed: boolean): string {

  return "One thing makes today count: a weigh-in, a meal, a set, or 3,000 steps.";
}

function trendLine(weights: { date: ISODate; weight: number }[], date: ISODate): string | null {
  const now = sevenDayAverage(weights, date);
  if (now === null) return null;

  return `Trend ${now} lb, ${change} since ${monthDay(plan.phaseStart)}.`;
}
```
