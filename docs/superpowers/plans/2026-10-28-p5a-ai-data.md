**Goal:** The data, the plumbing and the Settings section that every later step of project 5 builds on:
- **One migration:** `profile.ai` (the per-person AI switch, default on), the synced `facts` and `takes` tables, and the server-only `ai_calls` table.
- **Named changes:** `setAi`, `rememberFact`, `editFact`, `forgetFact`, and `setVoice` now keeps the rest of the profile row.
- **The model client** in the Worker (`@anthropic-ai/sdk`, Claude Sonnet 5.5), with one text call and one structured-output call that never throw, and a fake-able `AiClient` interface.
- **The AI route plumbing:** the key, switch and daily-cap gate, `ai_calls` logging, and `GET /api/ai/status` (with a `?probe=1` real-call check).
- **Settings, ROCKY section:** the "Rocky's AI" switch, What Rocky knows (edit and forget), and "+ Tell Rocky something", which saves the note as written for everyone until P5c.

**Architecture:**
- **Worker side.** `app/ai/claude.server.ts` wraps the SDK. Every call returns an `AiResult` (a value and the token usage, or a reason), so a route never handles an exception. `app/ai/calls.server.ts` reads the switch, counts today's calls and writes `ai_calls`. `workers/api/ai.ts` holds the gate every AI route runs first and the status route, mounted on P4e's router in `workers/api/router.ts`.
- **Each AI route ships with the step that uses it.** P5b adds `/api/ai/take`, P5c `/api/ai/tell`, P5d `/api/ai/label`, P5e `/api/ai/describe`. Each adds one method to `AiClient`, one handler to `workers/api/ai.ts` and one line to the router, and reuses everything below.
- **Phone side.** `app/ai/client.ts` asks `/api/ai/status` once per page load and posts to AI routes with a timeout, treating every failure as "no answer". `app/ai/use-ai.ts` combines the switch, the server's answer and the signal into one `ready` flag.
- **Settings reads the store,** like every screen since F2. The switch and the facts are named changes, so they work offline and sync.

**Tech Stack:** React Router 8.4 in SPA mode (P4f), Cloudflare Workers (D1), `@anthropic-ai/sdk` 1.3 with Zod 4 structured outputs, the F2 sync layer, Tailwind 4 with the Corner tokens, Vitest 4 (`unit` project in Node, `workers` project against real D1).

## Calls made in this plan (flag them when shipping)

- **The AI routes ship with the step that uses them, not all in P5a.** The spec's rollout lists the four AI routes under P5a. Each route's checks live in the module its own step builds (`checkTake` in P5b, the proposal checks in P5c, the food table in P5e), so P5a ships the shared parts every route needs (the client, the gate, the caps, `ai_calls`, `status`) and each later step adds its route on top. Nothing on the phone called the AI routes before their step anyway.
- **The routes live in `workers/api/ai.ts` on P4e's router,** not in a separate `workers/ai.ts` mounted in `workers/app.ts` as the spec drew it. P4e put every endpoint behind `routeApi`, which already does the session check and the 405s.
- **`GET /api/ai/status?probe=1` makes one tiny real model call** and reports whether it worked. The spec's status route makes no model call; plain `status` still doesn't. The probe exists so a deploy can be checked against Anthropic itself without opening a check-in. It runs the same gate as the other routes (key, switch, a cap of 5 a day), is logged in `ai_calls` as kind `probe`, and costs a fraction of a cent.
- **Structured outputs go through `messages.create` with `zodOutputFormat(schema)` as the format, and the reply is parsed here with the same schema.** The spec says `client.messages.parse`. That helper throws on a refused or cut-off reply while parsing it, before the stop reason can be read, so `ai_calls` would log `bad-output` where the reason is `refusal` or `max-tokens`. The API still constrains the reply to the schema; only the parse moves.
- **`nodejs_compat` replaces `nodejs_als` in `wrangler.jsonc`.** The SDK's credential loader has a dynamic `import()` of a module that imports `node:fs` and `node:os`. The Worker never runs it (the key is always passed), but the bundler has to resolve it. `nodejs_compat` includes `AsyncLocalStorage`, which is all `nodejs_als` gave.
- **Daily caps** are the spec's (30 describes, 20 labels, 20 tells), plus 6 take calls a day (P5b also caps take writes at 3 a week) and 5 probes. A take whose check fails stores nothing, so without a daily cap a week of repeat opens could keep calling.
- **`aiAvailable` answers `null` when it couldn't ask** (offline, signed out, a 5 second timeout), and that answer is not kept, so the next screen asks again. Only the server's own `false` shows "Not set up on this server yet".
- **The switch's copy uses ink-3,** as the `Settings` artboard draws it (#4A443C); the spec's table says ink-2. **The switch is the system's 50 × 30 `Toggle`;** the artboard draws 56 × 32.
- **The copy includes label reading,** as the board's issues list asked: "Writes Rocky's take, reads "Tell Rocky" notes and nutrition labels, and turns a described meal into a plate. Never changes your numbers. Off means written lines only."
- **Until P5c, the Tell Rocky sheet saves as written for everyone.** With the AI off or no key its note is the spec's "Rocky's AI is off, so this is saved as written."; with the AI on it reads "This is saved as written.", because saying the AI is off would be wrong. P5c gives the AI-on path its real sheet.
- **The save-as-written box holds 200 characters,** the fact limit, so Save can't send a note `rememberFact` would refuse. P5c's AI box holds the spec's 500.
- **A fact's date** is its `created_at` in Chicago ("Oct 25"), shown only when `dated` is 1.
- **`ANTHROPIC_API_KEY` is typed optional in `app/ai/env.d.ts`** and stays out of `secrets.required`, as the spec says. `.dev.vars.example` gains a commented line naming it.

```ts
// The one place the app talks to the model (spec section 1, "The model call"). Worker only: the key never reaches a
// phone. Every call comes back as an AiResult, never a throw, so each route falls back to the rules the same way.
import Anthropic from "@anthropic-ai/sdk";
import { zodOutputFormat } from "@anthropic-ai/sdk/helpers/zod";
import type { z } from "zod";
import { PROBE_SYSTEM } from "./prompts.server";

/** One constant, so a model change is one line. */
export const AI_MODEL = "claude-sonnet-5-5";

export type AiKind = "take" | "describe" | "label" | "tell" | "probe";
export type AiReason = "no-reply" | "refusal" | "max-tokens" | "bad-output" | "numbers" | "length" | "characters" | "rate-limit" | "error";

export interface AiUsage {
  input: number;
  output: number;
  cacheRead: number;
}

export type AiResult<T> = { ok: true; value: T; usage: AiUsage } | { ok: false; reason: AiReason; usage: AiUsage | null };

/** The calls the AI routes make. Worker tests hand the routes a fake. Each step of project 5 adds its call here. */
export interface AiClient {
  /** A tiny call that proves the key and the model work, for the wire check. */
  probe(): Promise<AiResult<string>>;
}

export interface ClientOptions {
  /** Tests pass a fake, so no request leaves the machine. */
  fetch?: typeof fetch;
  maxRetries?: number;
}

/** Made per request: one retry, and 15 seconds a try. */
export function anthropic(key: string, opts: ClientOptions = {}): Anthropic {
  return new Anthropic({ apiKey: key, maxRetries: opts.maxRetries ?? 1, timeout: 15_000, ...(opts.fetch ? { fetch: opts.fetch } : {}) });
}

export interface CallSpec {
  system: Anthropic.TextBlockParam[];
  content: Anthropic.ContentBlockParam[];
  /** "low" for describe, label and tell; "medium" for the take. */
  effort: "low" | "medium";
  maxTokens: number;
}

const usageOf = (m: Anthropic.Message): AiUsage => ({ input: m.usage.input_tokens, output: m.usage.output_tokens, cacheRead: m.usage.cache_read_input_tokens ?? 0 });

/** Most specific first. In this SDK a connection error is also an APIError, so it is checked before it. */
function failureOf(err: unknown): AiReason {
  if (err instanceof Anthropic.RateLimitError) return "rate-limit";
  if (err instanceof Anthropic.APIConnectionError) return "error";
  if (err instanceof Anthropic.APIError) return "error";
  return "error";
}

// No temperature (a 400 on this API version) and no thinking parameter: Sonnet 5.5 runs adaptive thinking, and
// { type: "disabled" } is a 400 on it. Effort is the dial. No assistant prefill, which is a 400 too.
async function send(client: Anthropic, spec: CallSpec, format?: Anthropic.JSONOutputFormat): Promise<Anthropic.Message | AiReason> {
  try {
    return await client.messages.create({
      model: AI_MODEL,
      max_tokens: spec.maxTokens,
      system: spec.system,
      messages: [{ role: "user", content: spec.content }],
      output_config: format ? { effort: spec.effort, format } : { effort: spec.effort },
    });
  } catch (err) {
    return failureOf(err);
  }
}

function stopped(m: Anthropic.Message): AiReason | null {
  if (m.stop_reason === "refusal") return "refusal";
  if (m.stop_reason === "max_tokens") return "max-tokens";
  return null;
}

function firstText(m: Anthropic.Message): string | null {
  for (const block of m.content) if (block.type === "text") return block.text;
  return null;
}

/** A plain reply: the first text block, trimmed. */
export async function textCall(client: Anthropic, spec: CallSpec): Promise<AiResult<string>> {
  const m = await send(client, spec);
  if (typeof m === "string") return { ok: false, reason: m, usage: null };
  const usage = usageOf(m);
  const stop = stopped(m);
  if (stop) return { ok: false, reason: stop, usage };
  const text = firstText(m)?.trim();
  return text ? { ok: true, value: text, usage } : { ok: false, reason: "no-reply", usage };
}

/**
 * A reply in the schema's shape. The schema goes to the API as structured output, then the reply is parsed here with
 * the same schema, so bounds the API doesn't enforce (lengths, ranges) still hold. Parsed here rather than by
 * messages.parse, which throws on a refused or cut-off reply before its stop reason can be read.
 */
export async function structuredCall<S extends z.ZodType>(client: Anthropic, spec: CallSpec & { schema: S }): Promise<AiResult<z.infer<S>>> {
  const { type, schema } = zodOutputFormat(spec.schema);
  const m = await send(client, spec, { type, schema });
  if (typeof m === "string") return { ok: false, reason: m, usage: null };
  const usage = usageOf(m);
  const stop = stopped(m);
  if (stop) return { ok: false, reason: stop, usage };
  const text = firstText(m);
  if (!text) return { ok: false, reason: "no-reply", usage };
  let json: unknown;
  try {
    json = JSON.parse(text);
  } catch {
    return { ok: false, reason: "bad-output", usage };
  }
  const parsed = spec.schema.safeParse(json);
  return parsed.success ? { ok: true, value: parsed.data as z.infer<S>, usage } : { ok: false, reason: "bad-output", usage };
}

/** The real client, over the SDK. */
export function anthropicClient(key: string, opts: ClientOptions = {}): AiClient {
  const client = anthropic(key, opts);
  return {
    probe: () => textCall(client, { system: [{ type: "text", text: PROBE_SYSTEM }], content: [{ type: "text", text: "Are you there?" }], effort: "low", maxTokens: 1000 }),
  };
}
```

```ts
// The /api/ai/* routes (spec section 1, "Endpoints"). The router has already checked the session. Every route then
// runs aiGate (a key, the person's switch), parses its body, checks its daily cap, calls the model once, logs the
// call, and answers. A model failure is a 200 with the route's fallback shape; the phone treats it like a timeout.
import { env } from "cloudflare:workers";
import { anthropicClient, type AiClient, type AiKind, type AiReason, type AiResult } from "~/ai/claude.server";
import { aiSwitchOn, callsToday, DAILY_CAP, logAiCall } from "~/ai/calls.server";
import { serverNow } from "~/server/clock.server";
import { userD1 } from "~/server/current-user.server";

export interface AiDeps {
  key: () => string | undefined;
  client: (key: string) => AiClient;
}

const REAL: AiDeps = { key: () => env.ANTHROPIC_API_KEY || undefined, client: (key) => anthropicClient(key) };
let deps: AiDeps = REAL;

/** Tests swap in a fake model or a missing key. Returns the restore. */
export function setAiDeps(next: Partial<AiDeps>): () => void {
  deps = { ...deps, ...next };
  return () => {
    deps = REAL;
  };
}

export const NO_STORE = { "Cache-Control": "no-store" } as const;

const FALLBACK_STATUS = { "no-key": 503, off: 403, cap: 429 } as const;

export function fallback(why: keyof typeof FALLBACK_STATUS): Response {
  return Response.json({ fallback: why }, { status: FALLBACK_STATUS[why], headers: NO_STORE });
}

export interface AiCall {
  ai: AiClient;
  /** The signed-in person's database. */
  d1: D1Database;
  now: Date;
}

/** A key, then the person's switch. Removing the secret turns every AI path off within one request. */
export async function aiGate(): Promise<AiCall | Response> {
  const key = deps.key();
  if (!key) return fallback("no-key");
  const d1 = userD1();
  if (!(await aiSwitchOn(d1))) return fallback("off");
  return { ai: deps.client(key), d1, now: serverNow() };
}

export async function overCap(call: AiCall, kind: AiKind): Promise<boolean> {
  return (await callsToday(call.d1, kind, call.now)) >= DAILY_CAP[kind];
}

/** One ai_calls row for the call. A reply the route's own check turned down is logged with that check's reason. */
export async function logged<T>(call: AiCall, kind: AiKind, result: AiResult<T>, refused: AiReason | null = null): Promise<void> {
  await logAiCall(call.d1, { kind, at: call.now, ok: result.ok && refused === null, reason: result.ok ? refused : result.reason, usage: result.usage });
}

/**
 * Whether the server has a key, with no model call; the phone keeps the answer for the page's life. `?probe=1` also
 * makes one tiny call through the same gate, so a deploy can be checked against Anthropic itself.
 */
export async function aiStatus(request: Request): Promise<Response> {
  const available = Boolean(deps.key());
  if (!available || new URL(request.url).searchParams.get("probe") !== "1") return Response.json({ available }, { headers: NO_STORE });
  const call = await aiGate();
  if (call instanceof Response) return call;
  if (await overCap(call, "probe")) return fallback("cap");
  const result = await call.ai.probe();
  await logged(call, "probe", result);
  return Response.json({ available, probe: { ok: result.ok, reason: result.ok ? null : result.reason } }, { headers: NO_STORE });
}
```

```ts
// The phone's side of the AI routes. Every failure (no key, switch off, cap, lost signal, slow model) comes back as
// null, and each screen shows its rule-written or typed path for null. No AI request is ever queued or retried.

const STATUS_WAIT_MS = 5_000;
let known: boolean | null = null;

/** Whether the server has a key, as last heard this page load. Null until it has answered. */
export function cachedAiStatus(): boolean | null {
  return known;
}

/** For tests: forget the answer, as a new page load would. */
export function forgetAiStatus(): void {
  known = null;
}

/**
 * Asks /api/ai/status once a page load. The server's answer is kept; a failed ask (offline, signed out, slow) is null
 * and isn't kept, so the next screen asks again.
 */
export async function aiAvailable(send: typeof fetch = fetch): Promise<boolean | null> {
  if (known !== null) return known;
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), STATUS_WAIT_MS);
  try {
    const res = await send("/api/ai/status", { signal: ctrl.signal });
    if (!res.ok) return null;
    known = ((await res.json()) as { available?: unknown }).available === true;
    return known;
  } catch {
    return null;
  } finally {
    clearTimeout(timer);
  }
}

/** POSTs to an AI route and waits up to `timeoutMs`. Null for any status but 200, no signal, or no answer in time. */
export async function postAi<T>(path: string, body: unknown, timeoutMs: number, send: typeof fetch = fetch): Promise<T | null> {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), timeoutMs);
  try {
    const res = await send(path, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(body), signal: ctrl.signal });
    return res.ok ? ((await res.json()) as T) : null;
  } catch {
    return null;
  } finally {
    clearTimeout(timer);
  }
}
```

```ts
  available: boolean | null;

  checking: boolean;
  online: boolean;
  /** An AI request can go now. Entry points that need a signal show "Needs a signal" when on and available but not ready. */
  ready: boolean;

export function useAi(): AiState {
  const on = aiOn(useTable("profile"));
  const online = useSyncStatus()?.online ?? true;
  const [available, setAvailable] = useState<boolean | null>(cachedAiStatus);
  const [settled, setSettled] = useState(false);

    if (available !== null || !online) return;

    setSettled(false);
    void aiAvailable().then((a) => {
      if (!live) return;
      setAvailable(a);
      setSettled(true);
    });
    return () => {
      live = false;
    };
  }, [available, online]);
  return { on, available, checking: available === null && online && !settled, online, ready: on && available === true && online };
}
```

```ts
export interface FactRow {
  key: string;
  /** The fact as saved, for the edit field. */
  text: string;
  /** As the row shows it, with " (Oct 25)" on a dated fact. */
  shown: string;
  /** The × button's label. */
  forget: string;
}

export interface RockySection {
  aiOn: boolean;
  /** Under the switch when the server has no key. */
  setupNote: string | null;
  facts: FactRow[];
  /** The line in place of the list when nothing is known yet. */
  empty: string | null;
  /** At the limit: the AI-off sheet says to forget one first. */
  full: boolean;
}

/** Settings' ROCKY section under the voice picker (spec section 5). `available` is null until the server has answered. */
export function rockySection(profile: Row[], facts: Row[], available: boolean | null): RockySection {
  const rows = factsOf(facts).map((f) => ({
    key: f.key,
    text: f.text,
    shown: f.dated ? `${f.text} (${MONTH_DAY.format(new Date(f.createdAt))})` : f.text,
    forget: `Forget: ${f.text}`,
  }));
  return {
    aiOn: aiOn(profile),
    setupNote: available === false ? `Not set up on this server yet, so ${COACH_NAME} uses written lines.` : null,
    facts: rows,
    empty: rows.length ? null : `Nothing yet. Tell ${COACH_NAME} something worth keeping in mind.`,
    full: rows.length >= FACT_LIMIT,
  };
}
```
